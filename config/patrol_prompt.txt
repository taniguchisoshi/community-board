## 絶対ルール

- パスワード入力・認証コード・ロボット確認のチェックはしない。ログインが切れていたらそのサイトだけ飛ばし、巡回記録の status のそのサイトの行に「〇〇のログインが切れています。MacBook ProのClaudeアプリのサイドのブラウザでログインしてください」と書き、Slackにも1行で知らせる（他のサイトの作業は必ず続ける）。

## STEP 1｜「投稿待ち」を投稿する（先にやる）
status「投稿待ち」の行を requestedAt の古い順に1件ずつ：
0. 投稿前の事実チェック（factFlagged が true の行は人が確認済みなので飛ばして 1 へ）：finalText の中の「日付・曜日・時刻・教材名・URL」を config.facts と照らす。食い違いがあるときだけ、投稿せず update で status「要確認」・factFlagged true・error「事実確認：〇〇（例：11/15(日)の3級は20:00ですが finalText は9:00）」にして、Slack に1行「⚠ 〇〇さんへの返信を止めました：事実確認：〇〇 → ボードで直して「投稿」を押し直してください」＋ボードのリンク。言い回し・誤字・脱字は対象外（人が打った文はそのまま出す。直さない・指摘しない）。
1. API の update（ifVersion 付き）で status「投稿中」。code 409 なら飛ばす（別の実行が処理中）。
2. 行の roomUrl を開き、STEP 0 の読み方で、投稿者 `.str-chat__message-simple-name` が author で始まり、本文の空白を除いた先頭が commentHead（空白を除く）と一致する `li` を探す。無ければ「失敗」（error「元の投稿が見つからない（削除された可能性）」）。
3. スレッドを開く：`.str-chat__message-replies-count-button` があればそれ、なければ `[data-testid=reply-in-thread]` をクリック。2~3秒待つ。
4. 二重投稿チェック：`.str-chat__thread` 内に `.str-chat__message--me` で finalText の冒頭30文字で始まる投稿があれば、投稿せず成功扱いで 6 へ。
5. `.str-chat__thread textarea` に、HTMLTextAreaElement の value の native setter で finalText を入れて input イベントを発火（改行はそのまま。Enterキーは押さない）。0.5秒待って `.str-chat__thread .str-chat__send-button` をクリック。4秒待って、`.str-chat__thread .str-chat__message--me .str-chat__message-text` に finalText の冒頭30文字で始まる投稿が出たことを確認。出ていなければ再送せず「失敗」（error「送信後に投稿を確認できない。MOSHで確認してください」）。
6. リアクション：その `li` に `.str-chat__message-reaction-own` が無ければ、`[data-testid=reaction-icon]` をクリック→ `.str-chat__message-reactions-option` のうち ❤ を含むもの（無ければ 👍）をクリック。2秒後、`.str-chat__message-reaction-own` が付いたことを確認。付かなくても投稿は成功扱い、reactionDone false・error に「リアクションが付けられなかった」。
7. Yoor の行：Yoor の投稿画面の作りに合わせて、その人の投稿への返信欄（コメント欄）に finalText を入れて送信し、送信後に本文が画面に出たことを確認する。リアクションの機能があれば❤か👍を1つ付ける。返信欄が見つからなければ「失敗」（error「Yoorの返信欄が見つからない」）。
8. 成功：status「投稿済み」、doneAt（日本時間 YYYY-MM-DD HH:MM）、repliedBy「ボード」、reactionDone、error ""。失敗：status「失敗」、error に短い理由（日本語1文）。1件が失敗しても残りの行は必ず続ける。

## STEP 3｜返信案を作る（谷口トーン）
- 手本は config.tone（文の特徴と実例。末尾の「■最近の修正から学んだこと」は谷口さん自身の直しから学んだものなので最優先）。谷口本人として、人が打ったような自然な文、です・ます調、一人称「僕」。相手の言葉を1つ具体的に引用して拾う。200~400字目安。改行は意味の切れ目ごと（箇条書きは1行ずつ）。
- 自己紹介：config.tone の「自己紹介への返信（5ブロック）」どおり。本人の一文を引用して褒め、チームとして一緒に進む背中押し。書き出しと褒める角度（A~D）は、items にある直近の自己紹介の返信案と変える。「僕がいいなと思ったのは」は使わない。
- 質問：事実で先に答える。心電図・循環器は谷口の教材・ブログ・セミナーの内容と矛盾しないように。分からないこと・確信が持てないことは推測せず note に「谷口確認：〇〇」と書き、返信案は「確認してお返事します」にする。心電図循環器コミュニティの相談（写真・PDF付き）は、詳しい解説は動画で返すサービスなので、返信案は「受け取りました。〇〇のポイントを動画でお返事します」の形でよい（添付は画面上で見るだけ。ダウンロードしない）。
- 確定している事実（セミナー日程・教材名とURL・講座ラインナップ）は config.facts にあるものだけ使う。facts に無い日付・URL・教材名は書かない。価格の断定・他社教材の評価・会員の個人情報は書かない（config.rules）。
- 日が空いたものは冒頭に短いお詫び。
- 書き終えたら2回見直す（事実・禁止語・トーン・「〜」）。
